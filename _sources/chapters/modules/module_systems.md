# 模块系统

编程语言的*模块系统*（module system），是这门语言为模块化编程提供的一整套机制。下面介绍模块系统通常关注的几个方面，并以 Java 和 OCaml 为主，对照两种语言中关系最密切的特性。

**命名空间。** *命名空间*（namespace）把一组通常具有逻辑关联的名称组织在一起，并与其他命名空间隔离开来。这样，同名的 `foo` 位于不同命名空间时，就可以表示不同的含义。因此，命名空间也是一种作用域机制，对模块化至关重要；没有它，一个程序员取的名称很容易与另一个程序员的名称发生冲突。Java 用类和包组织名称。OCaml 则使用我们很快会学到的*结构*（structure）。结构在组织名称这一点上与类相似，却没有构造函数、静态成员与实例成员、继承、重写、`this` 等面向对象机制带来的额外复杂度。结构是 OCaml 模块系统的核心。事实上，我们一直都在使用结构，只是还没有认真考察过它们。

**抽象。** *抽象*（abstraction）在隐藏一部分信息的同时，揭示另一部分信息，从而实现*封装*（encapsulation），也就是*信息隐藏*（information hiding）。模块的抽象机制通常会公开内部的某些名称，同时藏起另一些名称。因此，抽象刻画的是模块之间的一种关系：不同模块都可能满足同一个抽象。抽象对模块化不可或缺，因为实现者可以借此隐藏实现细节，防止客户端依赖甚至滥用这些细节；客户端也得以安心地忽略它们。在大型团队中，一个程序员设计的模块由此不易被他人误用，也没有谁必须掌握所有模块的全部细节。Java 通过接口和抽象类提供抽象；OCaml 则使用*签名*（signature），隐藏结构中的某些名称和定义。签名本质上就是结构的类型。

**代码重用。** 模块系统还会提供*代码重用*机制，让一个模块中的代码成为另一个模块的一部分，而无须手工复制。程序员因而可以在他人成果的基础上继续开发，同时保持代码易于维护：一个模块得到改进后，所有重用它的程序员都会自动受益。代码重用对模块化至关重要，因为它让我们能够反复组合各种“构件”，搭建出复杂的软件。在 Java 中，子类型和继承支持代码重用；在 OCaml 中，对应的机制是*函子*（functor）和 `include`。函子类似于函数，能够根据已有模块生成新模块；`include` 则像一种遵循规则的复制粘贴，把程序一处的代码纳入另一处。

```{warning}
Java 与 OCaml 之间的这些类比注定不够严密。读完上面的讨论，你很容易得出以下某一种印象：

- “结构就像 Java 类，签名就像接口。”

- “结构就像 Java 对象，签名就像类。”

两种说法都能帮助我们初步理解，却都不完全正确。因此，不妨暂时放下面向对象编程的类比，直接认识 OCaml 模块系统本身。与 Java 相比，它的构造方式确实另有一套思路。
```
