# OCaml 顶层

{{ video_embed | replace("%%VID%%", "3fzrFY-2ZQ8")}}

*顶层*（toplevel）就像 OCaml 的计算器或命令行界面。它有点类似于 Java 的 JShell，或者 Python 的交互式解释器。顶层很适合用来快速试验一些小段代码，而不用专门启动 OCaml 编译器。不过也别太依赖它，因为一旦要创建、编译和测试较大的程序，就需要更强的工具了。其他一些语言会把顶层称作 *REPL*，即 read-eval-print-loop：读取程序员输入、对其求值、打印结果，然后循环往复。

在终端窗口中输入 `utop` 启动顶层。按 `Control-D` 可以退出顶层。你也可以输入 `#quit;;` 然后回车。注意，这里的 `#` 必须真的输入；它不是屏幕上提示符里的那个 `#`。

## 类型和值

你可以在 OCaml 顶层中输入表达式。用双分号 `;;` 结束一个表达式，然后按回车。OCaml 会对该表达式求值，并告诉你结果值以及它的类型。例如：

```ocaml
# 42;;
- : int = 42
```

我们从右往左拆解一下 utop 的这条响应：

* `42` 是值。
* `int` 是这个值的类型。
* 这个值没有被赋予名字，所以显示的是符号 `-`。

上面这段 utop 交互是在书里“写死”的，我们必须把 `#`、`-` 等字符都手动打出来。不过，用来编写这本书的基础设施实际上支持我们直接写一些 OCaml 代码，并在书被转换为 HTML 或 PDF 时自动求值。从现在开始，我们一般都会用这种方式。它看起来像这样：

```{code-cell} ocaml
42
```

第一个带有 `42` 的代码块，是我们要求 OCaml 运行的代码。如果你想把它输入到 utop 中，可以直接复制粘贴。代码块右上角有一个图标，能方便地完成这件事。只不过别忘了在末尾补上双分号。第二个稍微缩进的代码块，则是这本书在构建时由 OCaml 产生的输出。

```{tip}
如果你是在浏览器中阅读本书，可以看一下右上角的下载图标。选择 `.md` 选项，就能看到这一页原始的 [MyST Markdown][myst] 源文件。你会发现，上面第二个示例的输出其实并不直接写在源文件里。这很好，因为这样输出会始终和构建本书时所使用的 OCaml 编译器版本保持一致，也意味着任何编译错误都能在构建阶段被发现，而不是等着你这个读者自己去踩坑。
```

你可以使用 `let` 定义把值绑定到名字上，例如：

```{code-cell} ocaml
let x = 42
```

这次我们从左往右拆解一下响应：

* 一个值被绑定到了某个名字上，所以会出现关键字 `val`。
* `x` 是这个值绑定到的名字。
* `int` 是这个值的类型。
* `42` 是这个值本身。

你可以把整条输出读作：“`x` 的类型是 `int`，它的值等于 `42`。”

## 函数

在顶层中，可以用如下语法定义函数：

```{code-cell} ocaml
let increment x = x + 1
```

我们来拆解一下这条响应：

* `increment` 是这个值所绑定到的标识符。
* `int -> int` 是这个值的类型。也就是说，这是一个接受 `int` 作为输入，并产生 `int` 作为输出的函数类型。你可以把箭头 `->` 看成一种视觉隐喻，表示一个值被“转换”为另一个值，而这正是函数所做的事。
* 这个值是一个函数。顶层不会把函数本身打印出来，因为函数已经被编译并以一种不便于美观显示的形式存在于内存中。所以顶层会打印 `<fun>`，把它当作一个占位符。

```{note}
`<fun>` 本身不是一个值。它只是表示“这里有一个无法直接打印出来的函数值”。
```

你可以用下面这样的语法来“调用”函数：

```{code-cell} ocaml
increment 0
```

```{code-cell} ocaml
increment(21)
```

```{code-cell} ocaml
increment (increment 5)
```

不过在 OCaml 中，更常见的说法不是“调用”函数，而是“应用”函数（apply）。

注意 OCaml 在括号和空格的写法上相当灵活。初学 OCaml 的一个难点，就是判断什么时候括号真的是必需的。所以，如果你碰到了语法错误，一个常见策略是先试着多加几个括号。不过，从风格上说，通常更推荐在不需要时省略括号。因此，`increment 21` 往往比 `increment(21)` 更好。

## 在顶层加载代码

除了定义函数，顶层还接受一些*指令*（directive）。这些并不是 OCaml 代码，而是告诉顶层本身去执行某个动作。所有指令都以字符 `#` 开头。最常见的指令之一大概就是 `#use`，它会把某个文件中的全部代码加载进顶层，就像你把该文件内容逐行敲进顶层一样。

例如，假设你创建了一个名为 `mycode.ml` 的文件，并在里面写入：

```ocaml
let inc x = x + 1
```

启动顶层。试着输入下面这个表达式，并观察报错：

```{code-cell} ocaml
:tags: ["raises-exception"]
inc 3
```

之所以会报错，是因为顶层目前还不知道有一个叫做 `inc` 的函数。现在向顶层输入以下指令：

```ocaml
# #use "mycode.ml";;
```

注意，上面第一个 `#` 是顶层提示符本身。第二个 `#` 才是你需要输入的，用来告诉顶层“这是一个指令”。如果没有第二个 `#`，顶层会以为你想去应用一个名为 `use` 的函数。

现在再试一次：

```{code-cell} ocaml
:tags: ["remove-cell"]
let inc x = x + 1
```

```{code-cell} ocaml
inc 3
```

## 顶层中的工作流

当你把代码保存在文件里，并配合顶层使用时，比较好的工作流是：

* 在文件中编辑代码。
* 用 `#use` 把代码加载进顶层。
* 在顶层里交互式测试代码。
* 退出顶层。**警告：这一步不要省略。**

```{tip}
假设你想修复代码中的一个 bug。你很容易产生这样的念头：不退出顶层，直接去编辑文件，然后在同一个顶层会话里再次执行 `#use`。请克制这种冲动。同一个会话中较早通过 `#use` 加载进来的“陈旧代码”会引发一些出人意料的现象，至少在你刚学这门语言的时候会如此。所以，**每次重新加载文件之前，都先退出顶层。**
```
