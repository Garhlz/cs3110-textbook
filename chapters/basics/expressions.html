2.3. 表达式#

OCaml 语法中最基本的组成单位是表达式。正如命令式语言中的程序主要由命令构成，函数式语言中的程序则主要由表达式构成。表达式的例子包括 2+2 和 increment 21。

OCaml 手册对语言中的所有表达式都给出了完整定义。虽然那个页面一开始的概述比较晦涩，但往下滚动之后就会看到一些英文解释。现在不必专门去研究它，只要知道以后可以把它当作参考资料即可。

在函数式语言中，计算的主要任务是把一个表达式求值为一个值。值是指那种已经没有任何剩余计算步骤的表达式。所以，所有值都是表达式，但并不是所有表达式都是值。值的例子有 2、true 和 "yay!"。

OCaml 手册也给出了所有值的定义，不过同样地，那一页更适合作为参考，而不是学习材料。

有时，一个表达式可能无法求值为某个值。这通常有两种原因：

  1. 对该表达式求值时抛出了异常。

  2. 对该表达式的求值永远不会终止（例如，它进入了“无限循环”）。

2.3.1. 原始类型和值#

原始类型是内建的、最基础的那些类型：整数、浮点数、字符、字符串和布尔值。它们和你在其他编程语言里见过的原始类型很相似。

类型 int：整数。 OCaml 的整数写法和通常一样：1、2 等。也可以使用常见运算符：+、-、*、/ 和 mod。其中后两者分别表示整数除法和取模：

65 / 60

- : int = 1

65 mod 60

- : int = 5

65 / 0

Exception: Division_by_zero.
Raised by primitive operation at unknown location
Called from Topeval.load_lambda in file "toplevel/byte/topeval.ml", line 93, characters 4-14

在现代平台上，OCaml 的整数范围是 \(-2^{62}\) 到 \(2^{62}-1\)。它们使用 64 位机器字（word）来实现，也就是 64 位处理器寄存器的大小。不过其中有一位会被 OCaml 实现“借走”，所以实际只剩 63 位表示整数。运行时使用这一位来区分整数和指针。若应用需要真正的 64 位整数，标准库中有一个 Int64 模块；若需要任意精度整数，则可以使用独立的 Zarith 库。不过对大多数用途来说，内建的 int 已经足够，而且性能最好。

类型 float：浮点数。 OCaml 的浮点数采用 IEEE 754 双精度浮点格式。在语法上，它们必须始终包含一个小数点，例如 3.14、3.0，甚至 3.。最后这个写法也是 float；如果写成 3，那它就是 int：

3.

- : float = 3.

3

- : int = 3

OCaml 有意不支持运算符重载。浮点数上的算术运算，运算符后面都带一个点。例如，浮点乘法写作 *.，而不是 *：

3.14 *. 2.

- : float = 6.28

3.14 * 2.

File "[7]", line 1, characters 0-4:
1 | 3.14 * 2.
    ^^^^
Error: The constant 3.14 has type float
       but an expression was expected of type int

OCaml 不会自动在 int 和 float 之间转换。如果你需要转换，可以使用两个内建函数：int_of_float 和 float_of_int。

3.14 *. (float_of_int 2)

- : float = 6.28

和任何语言一样，浮点表示都是近似的，因此会带来舍入误差：

0.1 +. 0.2

- : float = 0.300000000000000044

在 Python 和 Java 中也能观察到同样的现象。如果你以前还没遇到过，这里有一篇关于浮点表示的入门指南，读起来应该会很有意思。

类型 bool：布尔值。 布尔值写作 true 和 false。也可以使用常见的短路合取运算符 && 和短路析取运算符 ||。

类型 char：字符。 字符用单引号书写，例如 'a'、'b' 和 'c'。它们以字节的形式表示，也就是 ISO 8859-1 “Latin-1” 编码中的 8 位整数。这个范围中前半部分的字符就是标准 ASCII 字符。你可以用 char_of_int 和 int_of_char 在字符和整数之间转换。

类型 string：字符串。 字符串是字符序列，使用双引号书写，例如 "abc"。字符串连接运算符是 ^：

"abc" ^ "def"

- : string = "abcdef"

面向对象语言通常会提供一个可重写的方法，把对象转换成字符串，比如 Java 中的 toString() 或 Python 中的 __str__()。但大多数 OCaml 值都不是对象，因此需要别的办法来转换成字符串。对三种原始类型，OCaml 提供了内建函数：string_of_int、string_of_float 和 string_of_bool。比较奇怪的是，没有 string_of_char，不过库函数 String.make 可以达到同样的效果。

string_of_int 42

- : string = "42"

String.make 1 'z'

- : string = "z"

同样地，对这三种原始类型，也有从字符串进行转换的内建函数，只要转换是可行的：int_of_string、float_of_string 和 bool_of_string。

int_of_string "123"

- : int = 123

int_of_string "not an int"

Exception: Failure "int_of_string".

Raised by primitive operation at <unknown> in file "[14]", line 1, characters 0-26
Called from Topeval.load_lambda in file "toplevel/byte/topeval.ml", line 93, characters 4-14

没有 char_of_string，但可以通过从 0 开始的下标访问字符串中的单个字符。索引运算符写作点加方括号：

"abc".[0]

- : char = 'a'

"abc".[1]

- : char = 'b'

"abc".[3]

Exception: Invalid_argument "index out of bounds".

Raised by primitive operation at <unknown> in file "[17]", line 1, characters 0-9
Called from Topeval.load_lambda in file "toplevel/byte/topeval.ml", line 93, characters 4-14

2.3.2. 更多运算符#

上面我们已经介绍了大部分内建运算符，不过还有一些可以在 OCaml 手册里看到。

OCaml 中有两种相等性运算符：= 和 ==，对应的不等运算符则是 <> 和 !=。运算符 = 和 <> 检查的是结构相等（structural equality），而 == 和 != 检查的是物理相等（physical equality）。在还没学到 OCaml 的命令式特性之前，这两者的区别不太容易解释。如果你现在就感兴趣，可以查看 Stdlib.(==) 的文档。

重要

从现在开始就训练自己使用 =，不要使用 ==。如果你来自 Java 这类把 == 当作常规相等运算符的语言，这件事一开始会有些不习惯。

2.3.3. 断言#

表达式 assert e 会对 e 求值。如果结果是 true，那么不会发生更多事情，整个表达式会求值为一个名为 unit 的特殊值。这个 unit 值写作 ()，它的类型是 unit。但如果结果是 false，就会抛出异常。

测试函数 f 的一种方法，就是写下一系列这样的断言：

let () = assert (f input1 = output1)
let () = assert (f input2 = output2)
let () = assert (f input3 = output3)

这些断言表达的是：f input1 应当等于 output1，依此类推。这里的 let () = ... 用来接住每个断言返回的 unit 值。

2.3.4. if 表达式#

表达式 if e1 then e2 else e3 的含义是：如果 e1 求值为 true，那么整个表达式求值为 e2；否则求值为 e3。我们把 e1 称作这个 if 表达式的守卫（guard）。

if 3 + 5 > 2 then "yay!" else "boo!"

- : string = "yay!"

和你可能在命令式语言里见过的 if-then-else 语句不同，OCaml 里的 if-then-else 是表达式。它和其他表达式没有本质区别，可以出现在任何允许表达式出现的位置。这一点使它有点像其他语言中的三元运算符 ? :。

4 + (if 'a' = 'b' then 1 else 2)

- : int = 6

if 表达式可以很自然地嵌套：

if e1 then e2
else if e3 then e4
else if e5 then e6
...
else en

不管你写的是单个 if 表达式，还是高度嵌套的 if 表达式，都应该把最后那个 else 看成必不可少的部分。如果省略它，你很可能会得到一条目前还看不太懂的错误信息：

if 2 > 3 then 5

File "[20]", line 1, characters 14-15:
1 | if 2 > 3 then 5
                  ^
Error: The constant 5 has type int but an expression was expected of type
         unit
       because it is in the result of a conditional with no else branch

语法。 if 表达式的语法是：

if e1 then e2 else e3

这里的字母 e 用来表示任意 OCaml 表达式。它是一个语法变量，也叫元变量（metavariable）。它并不是 OCaml 程序本身中的变量，而是我们在描述语法时给某类语法结构起的名字。e 后面的数字只是为了区分这三次不同的出现。

动态语义。 if 表达式的动态语义是：

  • 如果 e1 求值为 true，并且 e2 求值为某个值 v，那么 if e1 then e2 else e3 求值为 v。

  • 如果 e1 求值为 false，并且 e3 求值为某个值 v，那么 if e1 then e2 else e3 求值为 v。

这些被称为求值规则（evaluation rules）：它们定义了表达式如何求值。注意，描述一个 if 表达式的求值，需要两条规则，一条处理守卫为真时的情况，另一条处理守卫为假时的情况。这里的字母 v 用来表示任意 OCaml 值，也是另一个元变量。稍后我们会学习一种更数学化的方式来表达动态语义；现在先使用这种较为非正式的说明方式。

静态语义。 if 表达式的静态语义是：

  • 如果 e1 的类型是 bool，并且 e2 的类型是 t、e3 的类型也是 t，那么 if e1 then e2 else e3 的类型就是 t。

这被称作一条类型规则（typing rule）：它描述了表达式如何进行类型检查。注意，描述 if 表达式的类型检查只需要一条规则。编译时在做类型检查时，并不关心守卫最后究竟会是真还是假；事实上，编译器根本无法预先知道守卫在运行时会得到什么值。这里的字母 t 用来表示任意 OCaml 类型。OCaml 手册也有所有类型的定义，不过有点奇怪的是，它并没有专门把 int、bool 这类基础类型单独列出来命名。

接下来我们会频繁写“has type”这种说法，所以不妨引入一个更紧凑的记号。以后凡是要写“e has type t”，我们就改写成 e : t。这个冒号读作 “has type”。这种用法和顶层在对输入表达式求值后给出的响应是一致的：

let x = 42

val x : int = 42

在这个例子里，变量 x 的类型是 int，而这正是冒号所表达的意思。

2.3.5. let 表达式#

到目前为止，我们用到 let 这个词时，通常是在顶层或 .ml 文件中写定义。例如：

let x = 42;;

val x : int = 42

这会把 x 定义为 42，之后我们就可以在顶层后续的定义中继续使用 x。这种 let 的用法我们称为*let 定义*（let definition）。

let 还有另一种用法，它本身就是一个表达式：

let x = 42 in x + 1

- : int = 43

这里我们把一个值绑定（bind）到名字 x 上，然后在另一个表达式 x + 1 中使用这个绑定。这种 let 的用法我们称为*let 表达式*（let expression）。既然它是表达式，它就会求值为某个值。这一点和定义不同，因为定义本身不会求值为任何值。如果你尝试把一个 let 定义放在原本应该出现表达式的位置，就能看出差别：

(let x = 42) + 1

File "[24]", line 1, characters 11-12:
1 | (let x = 42) + 1
               ^
Error: Syntax error

从语法上说，let 定义不能出现在 + 运算符的左边，因为那里需要的是一个值，而定义并不会求值为值。相比之下，let 表达式就完全没问题：

(let x = 42 in x) + 1

- : int = 43

理解顶层中的 let 定义，还有另一种方式：把它看成“还没把函数体补全的 let 表达式”。隐含地说，这个“函数体”就是你之后在顶层继续输入的所有内容。例如：

# let a = "big";;
# let b = "red";;
# let c = a ^ b;;
# ...

OCaml 对它的理解，相当于：

let a = "big" in
let b = "red" in
let c = a ^ b in
...

后一连串 let 绑定，正是惯用地在一段代码块中绑定多个变量的方式。

语法。

let x = e1 in e2

和往常一样，x 是一个标识符。这些标识符必须以小写字母开头，而不是大写字母；从风格上说，通常使用 snake_case，而不是 camelCase。我们把 e1 称为绑定表达式（binding expression），因为它是绑定给 x 的内容；把 e2 称为函数体表达式（body expression），因为它是绑定生效的那段代码主体。

动态语义。

对 let x = e1 in e2 求值时：

  • 先把 e1 求值为某个值 v1。

  • 再用 v1 替换 e2 中的 x，得到一个新表达式 e2'。

  • 然后把 e2' 求值为某个值 v2。

  • 这个 let 表达式的求值结果就是 v2。

例如：

    let x = 1 + 4 in x * 3
-->   (evaluate e1 to a value v1)
    let x = 5 in x * 3
-->   (substitute v1 for x in e2, yielding e2')
    5 * 3
-->   (evaluate e2' to v2)
    15
      (result of evaluation is v2)

静态语义。

  • 如果 e1 : t1，并且在假设 x : t1 的前提下可以推出 e2 : t2，那么 (let x = e1 in e2) : t2。

上面之所以加括号，只是为了更清楚。和往常一样，变量的类型通常由编译器的类型推断器自动推出来；当然程序员也可以显式写出类型标注，形式如下：

let x : t = e1 in e2

2.3.6. 作用域#

let 绑定只在它出现的那一块代码里生效。这一点和几乎所有现代编程语言一样。例如：

let x = 42 in
  (* y is not meaningful here *)
  x + (let y = "3110" in
         (* y is meaningful here *)
         int_of_string y)

一个变量的作用域（scope），就是它的名字有意义的那片区域。上面这个例子中，变量 y 只在绑定它的那个 let 表达式内部处于作用域中。

同一个名字的绑定也可能发生重叠。例如：

let x = 5 in
  ((let x = 6 in x) + x)

但这种写法相当让人困惑，因此从风格上强烈不推荐。尽管如此，我们还是来分析一下它的含义。

这段代码最终会求值成什么？关键在于：每次出现 x 时，它到底会被替换成什么值。以下是几种可能的替换方式：

(* possibility 1 *)
let x = 5 in
  ((let x = 6 in 6) + 5)

(* possibility 2 *)
let x = 5 in
  ((let x = 6 in 5) + 5)

(* possibility 3 *)
let x = 5 in
  ((let x = 6 in 6) + 6)

第一种是几乎任何正常语言都会采用的方式，也多半是你直觉上的答案。但，为什么？

答案和一个我们称为名称无关原则（Principle of Name Irrelevance）的思想有关：变量的名字本身不应该具有实质意义。你在数学里早就习惯了这一点。例如，下面这两个函数其实是一样的：

\[\begin{align*} f(x) &= x^2 \\ f(y) &= y^2 \end{align*}\]

把这个函数的参数叫做 \(x\) 还是叫做 \(y\)，本质上没有区别；它仍然是“平方函数”。因此，在程序里，下面这两个函数也应当被视为相同：

let f x = x * x
let f y = y * y

这个原则更常见的名字是 alpha equivalence（alpha 等价）：两个函数在变量重命名之后仍然等价。这种变量重命名有时也叫 alpha conversion，不过背后的历史缘由这里就不展开了。

根据名称无关原则，下面这两个表达式也应当相同：

let x = 6 in x
let y = 6 in y

那么，把它们嵌进更大的表达式里之后，下面这两个表达式也应该相同：

let x = 5 in (let x = 6 in x) + x
let x = 5 in (let y = 6 in y) + x

而要保证这两者真的相同，我们就必须选前面那三种可能性里的第一种。只有这样，变量名才真正无关紧要。

这种现象有一个常用术语：变量的新绑定会遮蔽（shadow）该名字的旧绑定。这个比喻很好理解：仿佛新绑定暂时在旧绑定上投下了阴影。不过等阴影退去，旧绑定还是会重新出现。

遮蔽并不是可变赋值。例如，下面两个表达式的结果都是 11：

let x = 5 in ((let x = 6 in x) + x)
let x = 5 in (x + (let x = 6 in x))

同样，下面这段 utop 交互记录也不是可变赋值，虽然一开始看起来很像：

# let x = 42;;
val x : int = 42
# let x = 22;;
val x : int = 22

回想一下，顶层中的每个 let 定义，本质上都等价于嵌套的 let 表达式。所以上面的代码实际上等价于：

let x = 42 in
  let x = 22 in
    ... (* whatever else is typed in the toplevel *)

正确的理解方式是：第二个 let 绑定的是一个全新的变量，只不过它碰巧和第一个 let 使用了同样的名字。

下面还有一段非常值得仔细研究的 utop 交互：

# let x = 42;;
val x : int = 42
# let f y = x + y;;
val f : int -> int = <fun>
# f 0;;
: int = 42
# let x = 22;;
val x : int = 22
# f 0;;
- : int = 42  (* x did not mutate! *)

总结一下：每个 let 定义都会绑定一个全新的变量。如果这个新变量恰好和旧变量同名，那么它会暂时遮蔽旧变量。但旧变量依然存在，而且它的值是不可变的，永远不会改变。所以，尽管 let 表达式表面上看起来有点像命令式语言中的赋值语句，但它们实际上完全不是一回事。

2.3.7. 类型注解#

OCaml 会自动推断每个表达式的类型，因此通常不需要程序员手动写出来。尽管如此，有时显式指定某个表达式应有的类型仍然很有用。类型注解（type annotation）就是为此服务的：

(5 : int)

- : int = 5

错误的类型注解会导致编译时错误：

(5 : float)

File "[27]", line 1, characters 1-2:
1 | (5 : float)
     ^
Error: The constant 5 has type int but an expression was expected of type
         float
  Hint: Did you mean 5.?

这个例子也说明了为什么类型注解在调试时有用。比如，也许你忘了 5 不能被当作 float 使用，于是写出了：

5 +. 1.1

那么你可能会试着手动注明 5 应该是一个 float：

(5 : float) +. 1.1

File "[28]", line 1, characters 1-2:
1 | (5 : float) +. 1.1
     ^
Error: The constant 5 has type int but an expression was expected of type
         float
  Hint: Did you mean 5.?

这时就能很清楚地看到：类型注解失败了。这个技巧在这个小例子上看起来也许有点笨，但在程序变大之后，往往会很有帮助。

重要

类型注解不是类型强制转换（type cast），比如 C 或 Java 中的那种。它并不表示把一个类型转换成另一个类型；它表示的是“检查这个表达式是否确实具有给定的类型”。

语法。 类型注解的语法是：

(e : t)

注意，这里的括号是必需的。

动态语义。 类型注解没有运行时意义。它会在编译时被消去，因为它表达的是一个编译时检查，而不是运行时转换。因此，如果 (e : t) 能成功编译，那么在运行时它就只是 e，并且会像 e 一样求值。

静态语义。 如果 e 的类型是 t，那么 (e : t) 的类型也是 t。
