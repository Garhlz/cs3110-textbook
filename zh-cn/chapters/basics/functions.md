# 函数

既然 OCaml 是一门函数式语言，那么关于函数自然有很多内容要讲。现在就开始。

```{important}
方法（method）和函数（function）不是同一个概念。方法是对象的组成部分，并且它隐含地带有一个接收者（receiver），通常通过 `this` 或 `self` 这样的关键字来访问。OCaml 的函数不是方法：它们不是对象的组成部分，也没有接收者。

有些人会说，所有方法都是函数，但不是所有函数都是方法。也有人会进一步区分函数和过程（procedure）：所谓过程，是那些不会返回任何有意义值的函数，例如 Java 中返回 `void` 的函数，或 Python 中返回 `None` 的函数。

所以，如果你来自面向对象背景，请务必注意术语。**本节里讨论的严格来说都是函数，不是方法。**
```

## 函数定义

{{ video_embed | replace("%%VID%%", "vCxIlagS7kA")}}

下面这段代码

```ocaml
let x = 42
```

其中确实包含了一个表达式（`42`），但它本身不是表达式，而是一个*定义*（definition）。定义会把值绑定到名字上；在这里，就是把值 `42` 绑定到名字 `x`。OCaml 手册对[定义][definitions]有所说明（参见该页中标题为 `definition` 的第三个大分组），不过和前面一样，那一页主要是参考资料，而不是学习材料。定义不是表达式，表达式也不是定义，它们属于不同的语法类别。

[definitions]: https://ocaml.org/manual/modules.html

现在，我们先聚焦于一种特殊的定义：*函数定义*。非递归函数的定义形式如下：

```ocaml
let f x = ...
```

{{ video_embed | replace("%%VID%%", "_x82qitu2R8")}}

递归函数的定义形式如下：

```ocaml
let rec f x = ...
```

两者的区别只在于关键字 `rec`。这一点可能多少有些令人意外，因为在大多数语言里，函数默认就可以递归调用自己，而你不用额外写一个关键字。不过 OCaml 并不作这种假设。（Scheme 语言家族也不这样。）

最著名的递归函数之一是阶乘函数。在 OCaml 中，它可以写成这样：

```{code-cell} ocaml
(** [fact n] is [n!].
    Requires: [n >= 0]. *)
let rec fact n = if n = 0 then 1 else n * fact (n - 1)
```

我们在函数上方写了规格注释，用来记录这个函数的前置条件（`Requires`）和后置条件（`is`）。

要注意的是，和许多语言一样，OCaml 的整数并不是“数学意义上的整数”，而是受限于固定比特宽度。[手册][man]规定，（有符号）整数至少有 31 位，但也可能更宽。随着体系结构的发展，这个大小也在增大。在当前实现中，OCaml 的整数是 63 位的。所以如果你用足够大的输入测试，可能会开始看到一些奇怪结果。问题不在 OCaml，而在机器算术本身。（有兴趣的读者也许会问：为什么是 31 或 63，而不是 32 或 64？这是因为 OCaml 的垃圾回收器需要区分整数和指针，因此运行时表示会借走一位，用来标记一个机器字是整数还是指针。）

[man]: https://ocaml.org/manual/values.html#sss:values:integer

下面是另一个递归函数：

```{code-cell} ocaml
(** [pow x y] is [x] to the power of [y].
     Requires: [y >= 0]. *)
let rec pow x y = if y = 0 then 1 else x * pow x (y - 1)
```

注意，在这两个函数里我们都没有写出类型：OCaml 编译器会自动替我们推断出来。编译器通过算法来解决这个*类型推断*问题，但我们自己其实也可以推出来。这有点像一则依靠推理来解开的谜题：

* 由于 `if` 表达式在 `then` 分支中会返回 `1`，根据 `if` 的类型规则，整个 `if` 表达式的类型就是 `int`。

* 既然这个 `if` 表达式的类型是 `int`，那么函数的返回类型也必须是 `int`。

* 由于 `y` 用相等运算符和 `0` 比较，所以 `y` 必须是 `int`。

* 由于 `x` 用 `*` 和另一个表达式相乘，所以 `x` 也必须是 `int`。

如果出于某种原因我们想把类型写出来，也可以这样写：

```ocaml
let rec pow (x : int) (y : int) : int = ...
```

给 `x` 和 `y` 写*类型注解*时，括号是必须的。通常我们会省略这些注解，因为让编译器自己推断会更简单。不过有时你也会想显式写出类型。特别有用的一种场景，是当编译器给出你看不懂的类型错误时。显式标注类型往往有助于调试这类错误信息。

**语法。**
函数定义的语法是：

```ocaml
let rec f x1 x2 ... xn = e
```

其中，`f` 是一个元变量，表示用作函数名的标识符。这些标识符必须以小写字母开头。关于小写标识符的其余[规则][lowercase]，可以在手册中查到。名字 `x1` 到 `xn` 也是元变量，表示参数标识符，它们遵循和函数标识符相同的规则。如果 `f` 是递归函数，就必须写关键字 `rec`；否则可以省略。

[lowercase]: https://ocaml.org/manual/lex.html#lowercase-ident

注意，这里给出的函数定义语法其实是经过简化的，比 OCaml 实际允许的写法更少一些。接下来几周，我们会学习更多函数定义的扩展语法。不过现在先用这个简化版本，有助于把注意力集中在核心概念上。

相互递归函数可以使用关键字 `and` 来定义：

```ocaml
let rec f x1 ... xn = e1
and g y1 ... yn = e2
```

例如：

```{code-cell} ocaml
(** [even n] is whether [n] is even.
    Requires: [n >= 0]. *)
let rec even n =
  n = 0 || odd (n - 1)

(** [odd n] is whether [n] is odd.
    Requires: [n >= 0]. *)
and odd n =
  n <> 0 && even (n - 1);;
```

函数类型的语法是：

```ocaml
t -> u
t1 -> t2 -> u
t1 -> ... -> tn -> u
```

这里的 `t` 和 `u` 是表示类型的元变量。类型 `t -> u` 表示一个函数：它接受一个 `t` 类型的输入，并返回一个 `u` 类型的输出。类似地，`t1 -> t2 -> u` 可以理解为：一个函数接受两个输入，第一个类型是 `t1`，第二个类型是 `t2`，并返回一个类型为 `u` 的结果。更一般地，也可以扩展到接受 `n` 个参数的函数。

**动态语义。** 函数定义本身没有动态语义，因为这里并没有什么需要求值的东西。OCaml 只是记录下：名字 `f` 绑定到了一个具有参数 `x1..xn` 和函数体 `e` 的函数上。真正发生求值，是在这个函数之后被应用的时候。

**静态语义。** 函数定义的静态语义是：

* 对于非递归函数：如果在假设 `x1 : t1`、`x2 : t2`、...、`xn : tn` 的前提下，可以推出 `e : u`，那么 `f : t1 -> t2 -> ... -> tn -> u`。
* 对于递归函数：如果在假设 `x1 : t1`、`x2 : t2`、...、`xn : tn`，以及 `f : t1 -> t2 -> ... -> tn -> u` 的前提下，可以推出 `e : u`，那么 `f : t1 -> t2 -> ... -> tn -> u`。

注意递归函数的类型检查规则是怎样工作的：它先假设函数标识符 `f` 具有某个特定类型，再去检查函数体在该假设下是否类型正确。这是因为 `f` 自己就在函数体的作用域中（就像参数也在作用域中一样）。

## 匿名函数

{{ video_embed | replace("%%VID%%", "JwoIIrj0bcM")}}

我们已经知道，值不一定非要绑定到某个名字上。比如，整数 `42` 就可以直接在顶层里输入，而不用先给它取名字：

```{code-cell} ocaml
42
```

当然，我们也可以把它绑定到一个名字上：

```{code-cell} ocaml
let x = 42
```

同样地，OCaml 的函数也不一定非得有名字；它们可以是*匿名的*。例如，下面就是一个把输入加一的匿名函数：

`fun x -> x + 1`

其中，`fun` 是表示匿名函数的关键字，`x` 是参数，而 `->` 用来分隔参数和函数体。

现在我们有两种写法来定义“加一函数”：

```{code-cell} ocaml
let inc x = x + 1
let inc = fun x -> x + 1
```

这两种写法在语法上不同，但在语义上是等价的。也就是说，虽然它们使用了不同关键字，也把一些标识符放在了不同的位置，但表达的意思完全一样。

{{ video_embed | replace("%%VID%%", "zHHCD7MOjmw")}}

匿名函数也叫 *lambda 表达式*。这个术语来自 *lambda calculus*（lambda 演算），它是一种计算的数学模型，就像图灵机也是一种计算模型一样。在 lambda 演算中，`fun x -> e` 会写作 $\lambda x . e$。其中的 $\lambda$ 就表示匿名函数。

现在你可能会觉得有点奇怪：为什么我们需要没有名字的函数？先不用担心。后面的课程里我们会看到它们的很多好用途，尤其是在学习所谓的“高阶编程”时。特别是，我们经常会创建匿名函数，并把它们作为输入传给其他函数。

**语法。**

```ocaml
fun x1 ... xn -> e
```

**静态语义。**

* 如果在假设 `x1 : t1`、`x2 : t2`、...、`xn : tn` 的前提下，可以推出 `e : u`，那么 `fun x1 ... xn -> e : t1 -> t2 -> ... -> tn -> u`。

**动态语义。** 匿名函数本身已经是一个值，因此没有进一步需要执行的计算。

## 函数应用

{{ video_embed | replace("%%VID%%", "fgCTDhXAYnQ")}}

这里我们讲的是一个经过适度简化的函数应用语法，比 OCaml 实际允许的写法稍简单一些。

**语法。**

```ocaml
e0 e1 e2 ... en
```

第一个表达式 `e0` 是函数，它被应用到参数 `e1` 到 `en` 上。注意，与包括 Java 在内的 C 家族语言不同，在 OCaml 中表示函数应用时，不需要额外用括号把参数包起来。

**静态语义。**

* 如果 `e0 : t1 -> ... -> tn -> u`，并且 `e1 : t1`、...、`en : tn`，那么 `e0 e1 ... en : u`。

**动态语义。**

对 `e0 e1 ... en` 求值时：

1. 先把 `e0` 求值成一个函数；同时把参数表达式 `e1` 到 `en` 也分别求值成 `v1` 到 `vn`。

   对于 `e0` 而言，结果可能是一个匿名函数 `fun x1 ... xn -> e`，也可能是某个名字 `f`。在后一种情况下，我们需要找到 `f` 的定义，并且可以假定它的形式是 `let rec f x1 ... xn = e`。不管是哪种情况，现在我们都已经知道了参数名 `x1` 到 `xn`，以及函数体 `e`。

2. 用每个值 `vi` 去替换函数体 `e` 中对应的参数名 `xi`，从而得到一个新的表达式 `e'`。

3. 再把 `e'` 求值为某个值 `v`，这就是 `e0 e1 ... en` 的求值结果。

如果你把这些求值规则和 `let` 表达式的规则比较一下，就会发现它们都依赖于“替换”这件事。这并不是巧合。事实上，程序中任何一个 `let x = e1 in e2`，我们都可以把它替换成 `(fun x -> e2) e1`。它们语法不同，但语义等价。从本质上说，`let` 表达式只是匿名函数应用的语法糖。

## 管道

{{ video_embed | replace("%%VID%%", "arS9kEqCFEU")}}

OCaml 内建了一个用于函数应用的中缀运算符，叫做*管道运算符*（pipeline operator），写作 `|>`。你可以把它想象成一个朝右的三角形。这个隐喻的意思是：值会沿着管道从左向右流动。比如，假设我们已经有上面那个加一函数 `inc`，另外再定义一个把输入平方的函数 `square`：

```{code-cell} ocaml
let square x = x * x
```

下面是两种等价的“把 5 先加一，再平方”的写法：

```{code-cell} ocaml
square (inc 5);;
5 |> inc |> square;;
```

后一种写法使用管道运算符，让 `5` 先经过 `inc`，再把结果送进 `square`。这是一种很好、也很符合 OCaml 习惯的表达方式。前一种写法则相对没那么优雅：它需要额外的括号，也要求读者的视线在表达式之间来回跳跃，而不是从左到右线性阅读。随着需要应用的函数越来越多，后一种写法也更容易扩展；前一种写法则会堆出越来越多的括号：

```{code-cell} ocaml
5 |> inc |> square |> inc |> inc |> square;;
square (inc (inc (square (inc 5))));;
```

一开始你可能会觉得这种写法有点奇怪，但下次当你发现自己正在写一长串函数应用时，不妨试着用一用管道运算符。

由于 `e1 |> e2` 其实只是 `e2 e1` 的另一种写法，所以我们无需单独给出 `|>` 的语义：它和普通函数应用完全相同。这两种程序又是一个“语法不同但语义等价”的例子。

## 多态函数

{{ video_embed | replace("%%VID%%", "UWmxYBEKzN8")}}

*恒等函数*（identity function）就是那个把输入原样返回的函数：

```{code-cell} ocaml
let id x = x
```

或者等价地，写成匿名函数：

```{code-cell} ocaml
let id = fun x -> x
```

这里的 `'a` 是一个*类型变量*：它表示某个未知类型，就像普通变量表示某个未知值一样。类型变量总是以单引号开头。常见的类型变量有 `'a`、`'b` 和 `'c`，OCaml 程序员通常会把它们念成希腊字母：alpha、beta、gamma。

我们可以把恒等函数应用到任何类型的值上：

```{code-cell} ocaml
id 42;;
id true;;
id "bigred";;
```

正因为 `id` 可以作用于多种类型的值，所以它是一个*多态*（polymorphic）函数：它可以作用于多种（poly）形式（morph）。

通过手动添加类型注解，我们可以把一个多态函数限制为比编译器自动推断出的更窄的类型。例如：

```{code-cell} ocaml
let id_int (x : int) : int = x
```

除了两个手写的类型注解外，这个函数和 `id` 是一样的。但正因为有了这些注解，我们就不能像对 `id` 那样，把 `id_int` 应用到一个 `bool` 上：

```{code-cell} ocaml
:tags: ["raises-exception"]
id_int true
```

另一种写 `id_int` 的方式是直接基于 `id`：

```{code-cell} ocaml
let id_int' : int -> int = id
```

从效果上说，我们拿到了一个类型为 `'a -> 'a` 的值，并把它绑定到了一个手动指定为 `int -> int` 的名字上。你可能会问：这为什么可行？毕竟这两个类型并不一样。

一种理解方式是从**行为**（behavior）的角度来看。`id_int` 的类型规定了它行为的一个方面：给它一个 `int` 作为输入，它承诺会返回一个 `int` 作为输出。而 `id` 其实也能作出同样的承诺：给它一个 `int`，它也会返回一个 `int`。当然，`id` 还能作出更多承诺，比如给它一个 `bool`，它会返回一个 `bool`。所以，当我们把 `id` 绑定到更严格的类型 `int -> int` 上时，只不过是把这些当前无关的额外承诺丢掉了而已。这样虽然丢失了信息，但至少不会违背承诺。因此，当我们需要一个 `int -> int` 类型的函数时，使用一个 `'a -> 'a` 类型的函数始终是安全的。

反过来则不成立。如果我们需要的是一个 `'a -> 'a` 类型的函数，却试图拿一个 `int -> int` 类型的函数来顶替，那么只要有人传入了别的类型，比如 `bool`，问题就会立刻暴露出来。为了防止这种情况，OCaml 在下面这段代码上会做一件可能有点出人意料的事：

```{code-cell} ocaml
let id' : 'a -> 'a = fun x -> x + 1
```

函数 `id'` 实际上并不是恒等函数，而是“加一函数”。因此，给它传 `bool`、`string` 或某个复杂数据结构都不安全；`+` 能安全处理的只有整数。所以 OCaml 会把类型变量 `'a` *实例化*为 `int`，从而阻止我们把 `id'` 应用于非整数：

```{code-cell} ocaml
:tags: ["raises-exception"]
id' true
```

这就引出了另一种、更机械的理解方式，也就是从**应用**（application）的角度来思考。这里说的“应用”，就是函数应用于参数时的那种应用：当我们对 `id 5` 求值时，参数 `x` 被值 `5` *实例化*。同样地，`id` 类型里的 `'a` 也在这个应用过程中被类型 `int` 实例化。所以，当我们写下

```{code-cell} ocaml
let id_int' : int -> int = id
```

实际上就是把 `id` 类型中的 `'a` 实例化成了 `int`。而且，就像我们没法“反向取消”一个函数应用一样，例如给定 `5`，我们没法倒推出它来自 `id 5`；同样，我们也没法撤销这次类型实例化，把 `int` 再变回 `'a`。

更精确地说，假设我们有一个 `let` 定义（或表达式）：

```ocaml
let x = e [in e']
```

而且 OCaml 为 `x` 推断出了某个类型 `t`，其中包含一些类型变量 `'a`、`'b` 等。那么这些类型变量是允许被实例化的。我们可以通过把函数应用到某些参数上来暴露出应当如何实例化（例如 `id 5`），也可以通过类型注解来实例化（例如 `id_int'`），等等。不过这种实例化必须保持一致。比如，我们不能把一个类型为 `'a -> 'b -> 'a` 的函数实例化为 `int -> 'b -> string`，因为 `'a` 在它两次出现的位置上就不再是同一个类型了：

```{code-cell} ocaml
:tags: ["raises-exception"]
let first x y = x;;
let first_int : int -> 'b -> int = first;;
let bad_first : int -> 'b -> string = first;;
```

## 带标签参数与可选参数

函数的类型和名字通常已经能让你大致猜出它的参数含义。不过，对于参数很多的函数，尤其是多个参数类型相同的情况，给参数加上标签会更有帮助。例如，你也许会猜 `String.sub` 这个函数是从给定字符串中取出一个子串，而这个猜测确实是对的。你可以在顶层里输入 `String.sub` 来查看它的类型：

```{code-cell} ocaml
String.sub;;
```

但仅从类型本身并不能清楚看出应当怎样使用它，你仍然得去查文档。

OCaml 支持带标签参数。你可以用下面的语法来声明这种函数：

```{code-cell} ocaml
let f ~name1:arg1 ~name2:arg2 = arg1 + arg2;;
```

调用这个函数时，可以按任意顺序传入带标签的参数：

```ocaml
f ~name2:3 ~name1:4
```

参数标签通常和对应变量名相同。针对这种情况，OCaml 提供了简写。下面两种写法是等价的：

```ocaml
let f ~name1:name1 ~name2:name2 = name1 + name2
let f ~name1 ~name2 = name1 + name2
```

是否使用带标签参数，很大程度上属于风格选择。它们能提供额外信息，但也会让类型签名显得更繁琐。

如果既想写带标签参数，又想给它加上显式类型注解，语法如下：

```
let f ~name1:(arg1 : int) ~name2:(arg2 : int) = arg1 + arg2
```

还可以把某些参数设为可选参数。调用时如果省略了这个参数，就会自动使用默认值。声明这种函数时，使用下面的语法：

```{code-cell} ocaml
let f ?name:(arg1=8) arg2 = arg1 + arg2
```

之后你既可以带参数调用它，也可以不带：

```{code-cell} ocaml
f ~name:2 7
```

```{code-cell} ocaml
f 7
```

## 部分应用

{{ video_embed | replace("%%VID%%", "85xVK0wmDTw")}}

我们可以这样定义一个加法函数：

```{code-cell} ocaml
let add x y = x + y
```

下面这个函数和它很相似：

```{code-cell} ocaml
let addx x = fun y -> x + y
```

函数 `addx` 接受一个整数 `x` 作为输入，并返回一个类型为 `int -> int` 的*函数*，它会把 `x` 加到传给它的任何值上。

`addx` 的类型是 `int -> int -> int`。`add` 的类型也是 `int -> int -> int`。所以从类型的角度看，它们是同一种函数。但 `addx` 的写法暗示了一个有趣的事实：我们可以只给它传一个参数。

```{code-cell} ocaml
let add5 = addx 5
```

```{code-cell} ocaml
add5 2
```

而事实证明，对 `add` 也同样可以这么做：

```{code-cell} ocaml
let add5 = add 5
```

```{code-cell} ocaml
add5 2;;
```

我们刚才做的事情叫做*部分应用*（partial application）：我们只给函数 `add` 提供了一个参数，尽管通常我们会把它视为一个多参数函数。之所以可行，是因为下面这三个函数*语法不同*，但*语义等价*。也就是说，它们只是表达同一计算的不同写法：

```ocaml
let add x y = x + y
let add x = fun y -> x + y
let add = fun x -> (fun y -> x + y)
```

所以 `add` 本质上是一个接受参数 `x`、并返回另一个函数 `(fun y -> x + y)` 的函数。这就引出了一个相当深刻的事实。

## 函数的结合性

准备好面对真相了吗？深呼吸一下。来了：

**每个 OCaml 函数都只接受一个参数。**

为什么？拿 `add` 来说，虽然我们写的是 `let add x y = x + y`，但我们已经知道它在语义上等价于 `let add = fun x -> (fun y -> x + y)`。更一般地，

```ocaml
let f x1 x2 ... xn = e
```

在语义上等价于

```ocaml
let f =
  fun x1 ->
    (fun x2 ->
       (...
          (fun xn -> e)...))
```

所以，尽管你会把 `f` 视为一个接受 `n` 个参数的函数，但从本质上说，它是一个接受 1 个参数、并返回另一个函数的函数。

像这样一个函数的类型：

```ocaml
t1 -> t2 -> t3 -> t4
```

真正的含义其实和下面一样：

```ocaml
t1 -> (t2 -> (t3 -> t4))
```

也就是说，函数类型是*右结合*（right associative）的：函数类型外面隐含着从右向左配对的括号。直观地说，一个函数先接受一个参数，然后返回一个还在等待其余参数的新函数。

而函数应用则是*左结合*（left associative）的：函数应用外面隐含着从左向右配对的括号。因此：

```ocaml
e1 e2 e3 e4
```

真正的含义其实是：

```ocaml
((e1 e2) e3) e4
```

这里的直觉是：最左边的表达式会抓取它右边紧邻的那个表达式，作为自己的单个参数。

## 把运算符当作函数

{{ video_embed | replace("%%VID%%", "OVKOx8UiwxM")}}

加法运算符 `+` 的类型是 `int -> int -> int`。通常我们把它写成*中缀*形式，例如 `3 + 4`。如果给它加上括号，我们就能把它变成*前缀*运算符：

```{code-cell} ocaml
( + )
```

```{code-cell} ocaml
( + ) 3 4;;
```

```{code-cell} ocaml
let add3 = ( + ) 3
```

```{code-cell} ocaml
add3 2
```

同样的技巧适用于任何内建运算符。

通常来说，这些空格其实不是必须的。我们既可以写 `(+)`，也可以写 `( + )`，但最好还是保留空格。乘法运算符尤其要当心，它*必须*写成 `( * )`，因为 `(*)` 会被解析为注释的开头。

我们甚至还可以自己定义新的中缀运算符，例如：

```ocaml
let ( ^^ ) x y = max x y
```

这样一来，`2 ^^ 3` 的结果就是 `3`。

不过，哪些标点符号可以用来构造中缀运算符，这套规则并不总是直观；这类运算符的优先级规则也同样不那么直观。所以用法上还是要谨慎。

## 尾递归

来看一个表面上没什么意思的函数。它从 1 一直“数到” `n`：

```{code-cell} ocaml
(** [count n] is [n], computed by adding 1 to itself [n] times.  That is,
    this function counts up from 1 to [n]. *)
let rec count n =
  if n = 0 then 0 else 1 + count (n - 1)
```

数到 10 没有问题：

```{code-cell} ocaml
count 10
```

数到 100,000 也没有问题：

```{code-cell} ocaml
count 100_000
```

但如果尝试数到 1,000,000，就会得到下面这个错误：

```
Stack overflow during evaluation (looping recursion?).
```

这是怎么回事？

**调用栈。** 问题在于，*调用栈*（call stack）的大小是有限的。你大概在入门编程课里学过，大多数语言都用栈来实现函数调用。栈里每一个元素都对应一个“已经开始、但还没完成”的函数调用。每个元素记录了局部变量的值、函数当前执行到哪条指令等信息。当一个函数体在求值过程中调用另一个函数时，就会有一个新的元素被压入调用栈；而被调用函数执行完毕后，这个元素又会弹出。

栈的大小通常受操作系统限制。因此，一旦栈空间耗尽，就无法再进行新的函数调用。正常情况下这不会发生，因为通常没有理由在返回之前连续进行那么多层函数调用。但一旦真的发生，操作系统让程序停止其实是合理的：否则它可能会不断吞噬整台计算机上的可用内存，从而影响同机运行的其他程序。`count` 函数本身不太可能造成这种后果，但下面这个函数就可能：

```{code-cell} ocaml
let rec count_forever n = 1 + count_forever n
```

所以，出于安全考虑，操作系统会限制调用栈的大小。这就意味着：对于足够大的输入，`count` 最终一定会把栈耗尽。注意，这个问题其实和具体的编程语言关系不大，因此它不仅会出现在 OCaml 中，也会出现在 Python、Java 等其他语言里。只是你可能不太容易在那里见到，因为你大概没有在那些语言里写过这么多递归函数。

**尾递归。** 这个问题有一个解决方案，最早见于 [Guy Steele 1977 年关于 LISP 的论文][lisp-tailcall]。这个解决方案叫做*尾调用优化*（tail-call optimization），它需要程序员和编译器之间做一点配合。程序员先对函数做一些改写，编译器识别出这种改写后，再施加优化。下面来看看它是如何工作的。

[lisp-tailcall]: https://dl.acm.org/doi/pdf/10.1145/800179.810196

假设一个递归函数 `f` 调用了它自己，然后直接返回这次递归调用的结果。我们的 `count` 函数*并不是*这样：

```{code-cell} ocaml
let rec count n =
  if n = 0 then 0 else 1 + count (n - 1)
```

因为在递归调用 `count (n - 1)` 之后，还有额外计算要做：计算机仍然需要把 `1` 加到那个调用的结果上。

但我们作为程序员，可以把 `count` 改写成一种形式，让它在递归调用之后*不再需要*额外计算。诀窍是写一个多带一个参数的辅助函数：

```{code-cell} ocaml
let rec count_aux n acc =
  if n = 0 then acc else count_aux (n - 1) (acc + 1)

let count_tr n = count_aux n 0
```

函数 `count_aux` 和原来的 `count` 几乎一样，只不过多了一个名为 `acc` 的参数。这是个惯用命名，表示“累加器”（accumulator）。它的思路是：我们最终希望函数返回的值，会随着每一次递归调用逐步累积到这个参数里。原本“剩余的计算”也就是“加 1”这件事，现在发生在递归调用*之前*，而不是*之后*。等递归最终触达基本情况时，函数直接返回 `acc`，因为答案已经累积好了。

不过，原来基本情况返回的 `0` 仍然得以某种形式出现在代码里。它确实还在，只不过变成了传给 `count_aux` 的初始累加器值。现在，`count_tr`（我们马上会解释名字里的 `tr`）就可以作为原始 `count` 的替代实现。

到这里为止，程序员这一边的工作就做完了。但你可能仍然会困惑：这么做到底有什么用？毕竟 `count_aux` 还是会像 `count` 一样递归调用自己很多次，最后不也还是会栈溢出吗？

这时就轮到编译器的职责了。一个好的编译器（OCaml 编译器在这方面就很好）能够识别出某次递归调用是否处于*尾位置*（tail position）。这是一种技术说法，意思是：“这个调用返回之后，不再有其他计算要做了。”`count_aux` 中的递归调用就在尾位置；`count` 中的递归调用则不在。把它们放在一起再看一遍：

```{code-cell} ocaml
:tags: ["remove-output"]
let rec count n =
  if n = 0 then 0 else 1 + count (n - 1)

let rec count_aux n acc =
  if n = 0 then acc else count_aux (n - 1) (acc + 1)
```

尾位置之所以重要，是因为：**处于尾位置的递归调用，不需要新的栈帧；它可以直接复用现有的栈帧。** 原因在于，现有栈帧里已经没有任何“以后还会用到”的信息了。既然没有剩余计算，那么局部变量、下一条待执行指令之类的信息都已经不再重要。这部分内存今后也不会再被读取，因为这一层调用实际上已经等同于结束了。所以，与其再分配一个新的栈帧浪费空间，编译器会直接“回收利用”前一个栈帧所占的空间。

这就是*尾调用优化*。它甚至不仅能用于递归函数；只要调用者的栈帧和被调用者足够兼容，这种优化在其他场景下也成立。而且，这个优化非常重要。它把栈空间需求从线性降到了常数级。原来的 `count` 需要 $O(n)$ 个栈帧，而 `count_aux` 只需要 $O(1)$，因为每次递归都在反复复用同一个栈帧。这也意味着 `count_tr` 真的可以数到 1,000,000：

```{code-cell} ocaml
count_tr 1_000_000
```

最后，为什么这个函数叫 `count_tr`？这里的 `tr` 就是 *tail recursive* 的缩写。尾递归函数指的是：它所有递归调用都处在尾位置。换句话说，它是一种不会把栈耗尽的递归函数，除非程序中还存在其他异常情况。

**尾递归的重要性。** 初学函数式编程的人有时会过度执着于尾递归。如果你现在只是在写某个函数的第一版实现，其实通常没必要一开始就为尾递归操心。真有需要的话，往后加一个累加器参数，往往就很容易把它改成尾递归。或者，也许你应该重新审视函数本身的设计。比如 `count` 这个例子，其实本来就有点傻。不过后面我们会见到一些并不傻的例子，比如遍历含有成千上万个元素的列表。

同样重要的是：编译器必须支持这种优化。否则你作为程序员对代码做的这些变换根本不会带来任何实际收益。事实上，大多数编译器都支持尾调用优化，至少会把它作为一个可选项。Java 是一个比较著名的例外。

**尾递归的配方。** 简单概括一下，把一个函数改写成尾递归的大致步骤是：

1. 把原函数改写成一个辅助函数，并加上一个额外参数：累加器，通常命名为 `acc`。
1. 再写一个新的“主函数”版本，负责调用辅助函数，并把原始基本情况的返回值作为累加器的初始值传进去。
1. 修改辅助函数，让它在基本情况时直接返回累加器。
1. 修改辅助函数的递归分支，让递归调用前就先把额外工作体现在累加器参数上。这一步往往最需要技巧。

**一个例子：阶乘。** 下面把这个阶乘函数改写成尾递归形式：

```{code-cell} ocaml
(** [fact n] is [n] factorial. *)
let rec fact n =
  if n = 0 then 1 else n * fact (n - 1)
```

第一步，改名并加上累加器参数：

```ocaml
let rec fact_aux n acc = ...
```

第二步，写一个新的“主函数”，用原来的基本情况返回值来初始化累加器：

```ocaml
let fact_tr n = fact_aux n 1
```

第三步，把辅助函数的基本情况改成返回累加器：

```ocaml
if n = 0 then acc ...
```

最后，改写递归分支：

```ocaml
else fact_aux (n - 1) (n * acc)
```

把这些拼起来，就得到：

```{code-cell} ocaml
let rec fact_aux n acc =
  if n = 0 then acc else fact_aux (n - 1) (n * acc)

let fact_tr n = fact_aux n 1
```

这是个不错的练习，不过实际收益可能也没那么大。因为在栈空间耗尽之前，这个计算就已经会先遭遇整数溢出了：

```{code-cell} ocaml
fact 50
```

要解决这个问题，我们得求助于 OCaml 的大整数库 [Zarith][zarith]。下面会用到一些超出目前课程范围的 OCaml 特性，但应该都不会太令人意外。（如果你想亲自运行这段代码，先用 `opam install zarith` 在 OPAM 里安装 Zarith。）

[zarith]: https://antoinemine.github.io/Zarith/doc/latest/Z.html

```{code-cell} ocaml
:tags: ["remove-cell"]
#use "topfind";;
```

```{code-cell} ocaml
:tags: ["remove-output"]
#require "zarith.top";;
```

```{code-cell} ocaml
let rec zfact_aux n acc =
  if Z.equal n Z.zero then acc else zfact_aux (Z.pred n) (Z.mul acc n);;

let zfact_tr n = zfact_aux n Z.one;;

zfact_tr (Z.of_int 50)
```

如果你愿意，甚至可以用这段代码去计算 `zfact_tr 1_000_000`，而且既不会栈溢出，也不会整数溢出，不过这会花上几分钟。

模块一章会更详细地解释上面用到的这些 OCaml 特性。现在先简单说明一下：

- `#require` 会加载这个库，而该库提供了一个名为 `Z` 的模块。回忆一下，数学中 $\mathbb{Z}$ 正是整数集合的符号。
- `Z.n` 表示模块 `Z` 内部定义的名字 `n`。
- 类型 `Z.t` 是这个库对“大整数类型”的命名。
- 我们使用库中的 `Z.equal` 做相等比较，`Z.zero` 表示 0，`Z.pred` 表示前驱（也就是减 1），`Z.mul` 表示乘法，`Z.one` 表示 1，而 `Z.of_int` 用来把原始整数转换成大整数。
