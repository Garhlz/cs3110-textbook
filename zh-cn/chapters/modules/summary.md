# 总结

OCaml 模块系统提供的模块化能力，与你在其他语言中见过的机制颇为相似。
不过，同一种机制以不同形式出现，反而能帮助我们加深理解。
例如，OCaml 的抽象类型和签名所提供的抽象能力，类似于 Java 的可见性修饰符和接口。
同一个思想在两种语言中以迥然不同的方式呈现，
会让你今后接触其他语言时更容易辨认出它。

此外，“类型也可以是抽象的”是编程语言设计中的一个基础观念，
OCaml 模块系统把这一点展现得格外鲜明。
Java 等语言把它与许多其他特性绑定在一起，反而略微遮蔽了这个事实。
从某种意义上说，每个 Java 类都会隐式定义抽象类型——准确地说，
四种可见性 [`public`、`protected`、`private` 和 `default`] 各对应一种抽象类型，
它们通过子类型关系彼此关联——而类中的所有方法，都是作用于这些抽象类型的函数。

函子是 OCaml 的一项高级语言特性，初看可能颇为神秘。
如果你也有这种感觉，请记住：函子其实就是一种以结构为输入、
以结构为输出的函数。它不像普通 OCaml 函数那样工作，
是因为结构在 OCaml 中不是一等值：普通函数不能接收或返回结构，
函子却恰好可以。

函子和 `include` 支持代码重用。面向对象特性能够实现的许多重用方式，
同样可以用函子和 `include` 完成。
当然，这并不意味着它们与面向对象特性完全等价：
有些重用方式用其中一套机制实现，会比用另一套更加容易。

我们可以这样理解：类扩展相当于一种能力有限却很实用的“函子加 `include`”。
扩展一个类，就好比编写一个函子，以基类为输入，将它 `include` 进来，再添加新函数。
函子比类扩展更通用，因为它可以对输入结构进行任意变换，而不限于少数几种扩展形式。

学习 OCaml 模块系统最重要的收获，也许是认识模块化中那些超越具体语言的要素：
命名空间、抽象和代码重用。看过这些思想如何在两门迥然不同的语言中组合起来，
以后学习新语言时，你就能更清楚地辨认出它们。
