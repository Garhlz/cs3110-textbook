# 记录和元组

{{ video_embed | replace("%%VID%%", "E3d1IFMU558")}}

单链表是很好的数据结构，但如果你想要固定数量的元素而不是无限个呢？或者想要元素有不同类型呢？或者想通过名称而不是位置来访问元素呢？列表在这些方面都不够方便。因此，OCaml 程序员使用记录和元组。

## 记录

*记录*是多个不同类型数据的组合，每个数据都有一个名称。OCaml 记录很像 C 中的结构体。下面是一个记录类型定义示例，定义了一个宝可梦（Pokémon）类型 `mon`，重用了 [变体](variants) 部分中定义的 `ptype`：

```{code-cell} ocaml
type ptype = TNormal | TFire | TWater
type mon = {name : string; hp : int; ptype : ptype}
```

这个类型定义了一个记录，有三个叫做 `name`、`hp`（生命值）和 `ptype` 的*字段*。每个字段的类型也被指定了。注意 `ptype` 既可以作为类型名称，也可以作为字段名称使用；这两个的*命名空间*在 OCaml 中是分开的。

为了构造一个记录类型的值，我们写一个记录表达式，看起来像这样：

```{code-cell} ocaml
{name = "Charmander"; hp = 39; ptype = TFire}
```

所以在类型定义中，我们在字段名称和类型之间写冒号，但在表达式中我们写等号。

要访问记录并从中获取字段，我们使用你在许多其他语言中期望的点记号。例如：

```{code-cell} ocaml
let c = {name = "Charmander"; hp = 39; ptype = TFire};;
c.hp
```

你也可以使用模式匹配来访问记录字段：

```{code-cell} ocaml
match c with {name = n; hp = h; ptype = t} -> h
```

这里的 `n`、`h` 和 `t` 是模式变量。有一个语法糖可用，当你想对字段名和模式变量使用相同的名称时：

```{code-cell} ocaml
match c with {name; hp; ptype} -> hp
```

这里，模式 `{name; hp; ptype}` 是 `{name = name; hp = hp; ptype = ptype}` 的语法糖。在每个子表达式中，等号左边出现的标识符是字段名，右边出现的标识符是模式变量。

**语法。**

记录表达式写成：

```ocaml
{f1 = e1; ...; fn = en}
```

记录表达式中 `fi=ei` 的顺序无关紧要。例如，`{f = e1; g = e2}` 完全等同于 `{g = e2; f = e1}`。

字段访问的写法是：
```ocaml
e.f
```
其中 `f` 必须是字段名称的标识符，而不能是一个表达式。这一限制与具有类似特性的其他语言相同——比如 Java 的字段名。如果你真的需要*计算*要访问哪个标识符，那实际上你需要的是一种不同的数据结构：*映射*（map）（还有许多其他名称，如 *dictionary*、*关联列表*、*哈希表*等，不过每个术语之间有细微差别）。

**动态语义。**

* 如果对所有 `i` ∈ `1..n` 都有 `ei ==> vi`，则 `{f1 = e1; ...; fn = en} ==> {f1 = v1; ...; fn = vn}`。

* 如果 `e ==> {...; f = v; ...}`，则 `e.f ==> v`。

**静态语义。**

记录类型的写法为：
```ocaml
{f1 : t1; ...; fn : tn}
```
记录类型中 `fi:ti` 的顺序无关紧要。例如，
`{f : t1; g : t2}` 完全等同于 `{g:t2;f:t1}`。

请注意，必须先定义记录类型，然后才能使用它们。  这个
使 OCaml 能够比以下情况进行更好的类型推断：
记录类型可以在没有定义的情况下使用。

类型检查规则是：

* 如果对所有 `i` ∈ `1..n` 都有 `ei : ti`，且 `t` 定义为 `{f1 : t1; ...; fn : tn}`，则 `{f1 = e1; ...; fn = en} : t`。注意，记录表达式中提供的字段集必须是该记录类型定义中字段集的完整集合（但请参见下面关于*记录复制*的内容）。

* 如果 `e : t1` 且 `t1` 定义为 `{...; f : t2; ...}`，则 `e.f : t2`。

**记录副本。**

还提供了另一种语法来从旧记录构造新记录：
```ocaml
{e with f1 = e1; ...; fn = en}
```
这不会改变旧记录。相反，它用新的内容构建新的记录
价值观。 `with` 之后提供的字段集不必是完整的
定义为记录类型一部分的字段集。在新复制的记录中，
未作为 `with` 的一部分提供的任何字段均从旧记录中复制。

记录副本是语法糖。相当于写
```ocaml
{ f1 = e1;   ...; fn = en;
  g1 = e.g1; ...; gn = e.gn }
```
其中 `gi` 的集合是记录类型的所有字段减去
`fi` 组。

**模式匹配。**

我们将以下新模式形式添加到合法模式列表中：

* `{f1 = p1; ...; fn = pn}`

我们扩展模式匹配值并产生绑定的定义如下：

* 如果对所有 `i` ∈ `1..n`，`pi` 匹配 `vi` 并产生绑定 $b_i$，则记录模式 `{f1 = p1; ...; fn = pn}` 匹配记录值 `{f1 = v1; ...; fn = vn; ...}`，并产生绑定集 $\bigcup_i b_i$。注意记录值中可以包含比记录模式中更多的字段。

作为语法糖，提供了另一种形式的记录模式：
`{f1; ...; fn}`。它会被去糖为 `{f1 = f1; ...; fn = fn}`。

## 元组

与记录类似，*元组*也是其他类型数据的组合。不过，元组不通过命名*组件*来区分，而是通过位置来区分。下面是一些元组的例子：
```ocaml
(1, 2, 10)
(true, "Hello")
([1; 2; 3], (0.5, 'X'))
```
具有两个组件的元组称为*对*（pair）。具有三个组件的元组称为*三元组*（triple）。超过三个组件之后，我们通常就直接说"元组"（tuple），而不再继续使用基于数字的命名方式。

```{tip}
对于超过三个组件的场合，可以说使用记录比使用元组更好，因为程序员很难记住每个位置上的组件应该表示什么信息。
```

构造元组非常简单：直接写出元组即可，如上所示。访问元组则通过模式匹配来完成，例如：
```{code-cell} ocaml
match (1, 2, 3) with (x, y, z) -> x + y + z
```

**语法。**

写了一个元组
```ocaml
(e1, e2, ..., en)
```
括号并不完全是强制性的 &mdash; 通常你的代码可以
成功解析没有它们&mdash; 但它们通常被认为是
良好的风格包括。

**动态语义。**

* 如果对所有 `i` ∈ `1..n` 都有 `ei ==> vi`，则 `(e1, ..., en) ==> (v1, ..., vn)`。

**静态语义。**

元组类型是使用新的类型构造函数`*`编写的，这是不同的
比乘法运算符。类型 `t1 * ... * tn` 是元组的类型
第一个组件的类型为 `t1`，...，第 n 个组件的类型为 `tn`。

* 如果对所有 `i` ∈ `1..n` 都有 `ei : ti`，则 `(e1, ..., en) : t1 * ... * tn`。

**模式匹配。**

我们将以下新模式形式添加到合法模式列表中：

* `(p1, ..., pn)`

括号也不是完全强制的，但通常是惯用的
包括。

我们扩展模式匹配值并产生绑定的定义如下：

* 如果对所有 `i` ∈ `1..n`，`pi` 匹配 `vi` 并产生绑定 $b_i$，则元组模式 `(p1, ..., pn)` 匹配元组值 `(v1, ..., vn)`，并产生绑定集 $\bigcup_i b_i$。注意元组值的组件数必须与元组模式的组件数完全相同。

变体和我们刚刚学到的类型（记录和元组）之间的核心区别在于：变体类型的值是若干可能性中的*之一*，而元组或记录类型的值则*同时*提供多种可能性的组合。回到我们的例子，类型 `day` 的值是 `Sun` 或 `Mon` 等中的**之一**。但类型 `mon` 的值则**同时**提供一个 `string`类型、一个 `int` 类型和一个 `ptype` 类型的值。注意，在前两句话中，"或"（or）这个词与变体类型相关联，而"且"（and）一词与元组和记录类型相关联。在决定使用变体还是元组/记录时，这是一个很好的线索：如果你需要一段数据*或*另一段数据，就用变体；如果你需要一段数据*且*另一段数据，就用元组或记录。

"之一"类型通常称为*和类型*（sum type），而"兼具"类型则称为*积类型*（product type）。这些名字来自集合论。变体就像[不相交并集][disjun]（disjoint union），因为变体的每个值都来自多个底层集合之一（到目前为止，每个集合仅包含一个构造函数，因此基数为 1）。不相交并集有时用求和运算符 $\Sigma$ 表示。元组/记录则像[笛卡尔积][cartprod]（Cartesian product），因为元组或记录的每个值都包含了来自每个底层集合的一个值。笛卡尔积常用乘积运算符 $\times$ 或 $\Pi$ 表示。

[disjun]: https://en.wikipedia.org/wiki/Disjoint_union
[cartprod]: https://en.wikipedia.org/wiki/Cartesian_product
